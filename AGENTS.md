# AGENTS.md: rules for every coding agent in this repository

SV KI-Lotse is a voice-first, screen-aware guide through Austria's health and social insurance system.

- **Requirements:** docs/prd/SV-KI-Lotse-PRD.md. Read the sections your brief references.
- **Process:** ORCHESTRATION.md.
- **Package rules:** every package and app has its own AGENTS.md with scope, commands, invariants and
  forbidden paths. Read it before you change anything there.

## Architecture in one paragraph

- One TypeScript brain (`packages/brain`) holds all business logic. It is hosted by the Next.js app
  (`apps/web`) and runs on AI SDK 7.
- One store: Postgres with pgvector and S3-compatible object storage hold all user context.
- One conversation client: the web workspace (`useChat`), in the browser and inside the Mac app's
  `WKWebView`.
- One protocol (`packages/protocol`, Zod → JSON Schema → Swift) is the only contract between brain,
  workspace and Mac app.
- The Mac app (`apps/mac`, SwiftUI/AppKit, derived from Clicky) is a capability provider over a typed
  bridge: it captures, transcribes, speaks, points and drives guided windows. It never runs a
  conversation.
- Benefits, processes, forms, offices, allowlists and guard patterns are data in `packages/knowledge`,
  never code.

## Rules for workers

- Work only on the work package (WP) you were given, and change only the paths its brief owns.
- Do not run git commands that write (commit, add, stash, checkout, reset, rebase, merge, branch, tag,
  push). The orchestrator commits.
- No mocks, fakes or simulated services in product code.
  - Acceptance tests run against real Postgres and MinIO (`docker compose up -d --wait`).
  - Where the brief lists `live_services`, they also run against the real provider, with keys from
    the environment (.env.local).
  - Test doubles are allowed only inside test files, for isolated units.
- Never weaken, skip or delete tests. Never use:
  - `.only`, `.skip`, `@ts-ignore`, `@ts-nocheck` or `any`;
  - `!`, `try!` or `as!` in Swift outside tests.
- Never print, log or commit secrets. Configuration comes from environment variables validated with
  Zod at startup.
- Never hand-edit generated files (protocol JSON Schema, Swift protocol types, migrations generated by
  drizzle-kit, lockfiles). Run the generator.
- Do not reference any benefit, scenario, form or office id in code (enforced by the E2 scan).
- Respect the medical boundary (PRD section 4) in every prompt, user-facing string and fixture:
  - no diagnosis, no interpretation of findings, no risk assessment, no therapy or medication advice;
  - only verbatim quotes of documented recommendations.
- If something outside your paths must change, stop and report a contract change request.
  These need no request and are always allowed:
  - updating `AGENTS.md` and `README.md` of a package or app in which you own paths (commands,
    invariants, how to run);
  - `@types/*` packages for libraries you already use, and `workspace:*` dependencies on packages
    whose public exports you import;
  - a library whose API the brief names (for example `embedMany` implies `ai`), at the version the
    rest of the repository uses;
  - test-only fixtures you construct from real data when the data cannot show a case on its own
    (say so in the test and the report).
  Stop only for real conflicts: a frozen contract (protocol, database schema, tool schemas), a path
  another WP owns, a new paid service, or a requirement that contradicts the PRD.
- Never delete, move or edit `KI-Challenge_UseCase.yaml` (required by the challenge).
- `data/svbox/` holds the original challenge files: read them (through `SVBOX_DIR`), never modify them.

## Engineering standards

- **TypeScript:**
  - strict mode, ESM only, Node.js 22+;
  - Zod at every boundary (HTTP, tools, protocol, YAML, env);
  - Biome for lint and format, Vitest for tests, Playwright for end-to-end tests;
  - small pure functions, typed errors, no default exports except where Next.js requires them.
- **Swift:**
  - Swift 6 language mode with strict concurrency for new modules;
  - SwiftLint;
  - XCTest or Swift Testing;
  - `@MainActor` for UI; no force unwraps;
  - new code lives in the `LotseKit` Swift package modules, never directly in the Xcode project.
- **Tests:** a test asserts behaviour, not implementation details. Name it after the requirement it
  proves (for example `FR-G3 asks only for missing slots`). Every bug fix comes with a regression test.
- **Logging:** structured, without user content, documents or form values.
- **Accessibility:** WCAG 2.2 AA in the workspace; VoiceOver labels and keyboard control on the Mac.
- **Names:** English for code and comments. German only where an official term is the domain name
  (Pflegegeld, Rezeptgebühr), in data and in user-facing copy.

## Commands

| Purpose | Command |
| --- | --- |
| Install | `bun install --frozen-lockfile` |
| All checks | `bun run verify` (Biome lint, then `turbo run typecheck test` across packages, cached) |
| One package | `bun run --filter @lotse/<package> <script>` or `bunx turbo run <task> --filter=@lotse/<package>` |
| Add a dependency | `bun add <name>` inside the package folder |
| Local services | `docker compose up -d --wait` (Postgres with pgvector, MinIO) |
| Live tests | `RUN_LIVE=1 bun run --filter <package> test:live` (calls the real OpenAI and ElevenLabs APIs) |
| Build-time stubs | `BRAIN_ALLOW_STUBS=1` lets unbuilt tools return schema-valid fixtures; never in a release |
| Mac project | `cd apps/mac && xcodegen generate` |
| Mac build and test | `xcodebuild -project apps/mac/SVKILotse.xcodeproj -scheme SVKILotse -destination 'platform=macOS' -derivedDataPath .build/dd CODE_SIGNING_ALLOWED=NO test` |

Bun installs packages and runs scripts; Node.js 22 is the runtime for Next.js and Vitest, so never
pass `--bun`. Always use `bun run <script>`: `bun test` and `bun build` are Bun's own test runner and
bundler, not the package scripts.

Some gates (Docker, xcodebuild, TCC permissions) may not run inside a sandbox. Run what you can and list
the rest under `not_run`; the orchestrator runs them outside the sandbox.
